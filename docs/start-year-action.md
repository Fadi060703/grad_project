# Start Year Action

## Endpoint

```http
POST /actions/start-year-action
```

Permission:

```text
actions:start-year-action
```

Only `ADMIN` has this permission.

---

## Request body

```json
{
  "confirm": true,
  "first_year_students": [
    {
      "student_id": 1001,
      "username": "student1001",
      "full_name": "Student Name",
      "mother_name": "Mother Name"
    }
  ],
  "major_assignments": [
    {
      "student_id": 2001,
      "major_id": 3
    }
  ]
}
```

- `confirm` must be `true`.
- `first_year_students` can be empty.
- `major_assignments` is required for every student currently in a year where `Year.has_majors = true`.
- Extra major assignments for students in non-major years are ignored.

All expected validation errors from this action are returned in Arabic.

---

## What the action does

The action runs inside one Prisma transaction.

1. Calculates the next academic key automatically.
   - Previous key must be empty/null or match `SECOND_YYYY`.
   - Empty/null previous key becomes `FIRST_{current calendar year + 1}`.
   - `SECOND_2026` becomes `FIRST_2027`.
2. Creates the submitted first-year students.
   - First year is the year with the smallest `Year.order`.
   - Passwords are generated by the backend.
   - New users are created with role `STUDENT`.
   - No explicit permissions are stored on the user row.
   - Students are created temporarily with the first available first-year group, then reassigned later in the same transaction.
3. Redistributes all students in the system.
   - Years without majors: students are shuffled equally across the year's sections.
   - Years with majors: each student is assigned to the requested `major_id`.
   - After section/major assignment, students are shuffled equally across groups in that section/major.
4. Attaches first-semester courses.
   - Only courses with `semester = FIRST` are attached.
   - Section students get courses linked through `SectionCourse`.
   - Major students get courses linked through `MajorCourse`.
   - Every student also gets direct year courses where the course has no section or major links.
   - Existing course attachments are kept, including failed courses from end-year action.
   - Students marked `is_failed = true` do not receive any new courses in this action.
   - Duplicate `StudentCourse` rows are skipped.
5. Generates a random unique 4-digit `exam_seat_number` for every current student.
6. Updates `system_settings.current_academic_key`.

---

## Response

The response only returns the first-year students created by this action with their generated passwords.

```json
{
  "success": true,
  "message": "تم تنفيذ إجراء بداية السنة بنجاح.",
  "data": {
    "created_students": [
      {
        "student_id": 1001,
        "username": "student1001",
        "full_name": "Student Name",
        "password": "Generated123"
      }
    ]
  }
}
```

The frontend should immediately download these returned credentials as an Excel file because passwords cannot be recovered later.
